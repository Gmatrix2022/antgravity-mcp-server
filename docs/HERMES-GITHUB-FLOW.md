# AntGravity ── Hermes 自动推送 GitHub 完整设计与指令流 (HERMES-GITHUB-FLOW)

> **设计背景**：当远程 Hermes 容器通过 MCP 协议向 Windows 主机派发任务时，最核心的场景是：
> 1. Hermes 通过 `ag_powershell` 派发代码修改/构建任务。
> 2. 任务完成后，需要在 Windows 本地将修改自动 Push 到 GitHub 仓库。
> 3. 本文档旨在规范 **Token 存放位置**、**远程 Git 仓库关联** 以及 **具体的 PowerShell 指令执行流**。

---

## 🔒 一、 GitHub Token 存放与安全策略

由于 `git push` 时需要验证权限，而在自动化脚本中无法通过弹窗输入账号密码，最稳妥、高效的方案是使用 **GitHub 个人访问令牌 (Personal Access Token, PAT)**。为了防止 Token 泄露，推荐以下两种设计：

### 方案 A：由 Hermes 运行时动态注入 (最推荐)
* **原理**：Token 存放在 Hermes 容器的安全环境变量（Secret）中。当 Hermes 派发任务时，将 Token 作为临时环境变量插入到 `ag_powershell` 的命令中。命令执行完后，Token 即随进程结束而销毁，不会永久写入 Windows 的系统变量或本地文件中。
* **执行命令模板**：
  ```powershell
  # 命令开头动态定义临时变量
  $env:GITHUB_TOKEN="ghp_xxxxYOUR_SECRET_TOKENxxxx"; ... 具体的 Git 提交推送流 ...
  ```

### 方案 B：保存在 Windows 本地受控文件
* **原理**：将 Token 保存在 Windows 用户的 Home 目录（例如 `C:\Users\keche\.git_token`）中。该路径处于 `D:\Obsidian\sync\` 同步白名单外，对公有云完全隔离。
* **读取命令模板**：
  ```powershell
  $env:GITHUB_TOKEN = Get-Content -Path "$env:USERPROFILE\.git_token" -Raw
  ```

## 📡 二、 具体的 Git 自动化指令序列

以下是专门为 `ag_powershell` 优化的**高鲁棒性、防报错**的 PowerShell 自动化指令序列。

### 核心设计细节（防坑指南）：
1. **本地身份注册**：Windows 本地若未配置 Git 全局用户名，Git 提交时会爆出 `Author identity unknown` 的致命错误导致中断。因此脚本中必须在本地仓库级显式声明 `user.name` 和 `user.email`。
2. **Token 安全脱敏（重要）**：如果直接 `git remote add origin https://token@github.com/...`，Token 会被持久化写入本地隐藏文件 `.git/config`。
   * **安全修复**：采用 **临时 Push 目标** 的安全做法，仅在 `git push` 指令中带入 Token，或者在 Push 完成后立即重置 Remote URL，防止泄露。

---

### 💻 完整 PowerShell 命令流

```powershell
# 1. 进入目标项目工作区
cd "D:\Obsidian\sync\task\antgravity-mcp-server";

# 2. 安全声明本地 Git 身份（防止 "Author identity unknown" 报错）
git config --local user.name "AntGravity";
git config --local user.email "antgravity@example.com";

# 3. 关联或更新不含敏感 Token 的基本远程仓库地址
$repoUrl = "github.com/您的用户名/antgravity-mcp-server.git";
$remoteExists = (git remote) -contains "origin";
if ($remoteExists) {
    git remote set-url origin "https://$repoUrl";
} else {
    git remote add origin "https://$repoUrl";
}

# 4. 暂存所有修改并做自动化本地提交
git add -A;
# 自动捕获当前时间戳作为提交日志
$timestamp = Get-Date -Format "yyyy-MM-dd HH:mm:ss";
git commit -m "auto: updates generated by Hermes on $timestamp";

# 5. 读取注入的 GitHub Token (以方案 A 临时注入为例)
$token = $env:GITHUB_TOKEN;

# 6. 使用 Token 执行安全推送 (Token 仅在推流时作为 URL 动态带入，不落盘)
git push "https://${token}@${repoUrl}" master:main --force;

# 7. 汇报推送结果
Write-Host "GitHub 自动推送成功于 $timestamp ✅";
```

## 📋 三、 Hermes 视角下的完整调用链

当 Hermes 想要向 Windows 的 `AntGravity` 派发一键上传的任务时，它只需发起如下 MCP `CallToolRequest` 请求：

```json
{
  "name": "ag_powershell",
  "arguments": {
    "command": "$env:GITHUB_TOKEN=\"ghp_您的GitHubPAT\"; cd \"D:\\Obsidian\\sync\\task\\antgravity-mcp-server\"; git config --local user.name \"AntGravity\"; git config --local user.email \"antgravity@example.com\"; git add -A; git commit -m \"auto: updates\"; git push \"https://${env:GITHUB_TOKEN}@github.com/您的用户名/antgravity-mcp-server.git\" master:main --force",
    "timeout": 60,
    "cwd": "D:\\Obsidian\\sync\\task\\antgravity-mcp-server"
  }
}
```

### 🏆 这样做带来的卓越效果：
- **无挂起危险**：完全避免了由于 Git 账户未登录而在 Windows 后台弹出凭据管理器 GUI 导致进程无限期挂死。
- **全自动化**：Hermes 可以在对代码做出任意微调后，直接通过此方式实现云端“自动上架”。
